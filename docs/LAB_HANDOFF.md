# 실습실 인수인계 (2026-11-13 회사 PC 작업분)

회사 PC에서 GitHub 코드를 기준으로 수정한 내용과, 실습실에서 `git pull` 후 해야 할 일을 정리한 문서다.
모든 기능은 **모의 로봇(mock)·시뮬레이션 웹**으로만 확인했다. 실제 로봇·RFID 리더기·웹캠·갤럭시 폰에서는 아직 확인하지 않았다.

---

## 1. 실습실에서 할 일 (순서대로)

### 1-1. 코드 받기와 실행
```bash
git pull                                   # 로봇 PC(리눅스)와 Windows PC 모두
python scripts/start_lab.py --host 0.0.0.0 # 로봇 PC: 웹 서버(8000). 음성을 쓰려면 YOLO_VOICE_ENABLED=1
python scripts/project_cycle.py --mode real --confirm-real --api http://127.0.0.1:8000 --remote-rfid --cycles 0 \
  --picking-config config/integration.real.json --depth-api http://127.0.0.1:8000 --vision yolo --box-check
```
- Windows PC: `windows_rfid_bridge\run_bridge.bat` → **RFID 태그 관제 프로그램**이 뜬다(첫 실행 때 `pillow`를 설치함).
  바탕화면 아이콘이 필요하면 `make_shortcut.bat`을 한 번 실행한다. 예전 콘솔은 `run_bridge_console.bat`.
- 웹은 서버만 재시작하면 바로 새 화면이 나온다(정적 파일 캐시 재검증 적용).
- **APK**: GitHub Actions `Build Galaxy Remote APK`로 다시 빌드해서 폰에 설치한다(1.1.0: 페이지 캐시 끄기, 진동 범위).
  폰 화면 자체는 서버 페이지라서 APK를 다시 안 깔아도 대부분 반영된다.

### 1-2. 처음 움직일 때 확인 (펜던트 E-Stop을 손에 쥐고, 로봇 주변을 비우고)
| 순서 | 확인할 것 | 기대 동작 |
|---|---|---|
| 1 | 폰 상단 배너 | "로봇 PC 사이클 연결됨" |
| 2 | 폰 [비상 정지] → [정지 해제] | 즉시 정지, 해제 후 홈 복귀 |
| 3 | 홈 → 일시정지/재개 → 리더기 스캔 출동 → 작업 시작 | 각 버튼에 결과 토스트 |
| 4 | 음성 "정지"·"스톱" / "잠깐"·"대기" | 비상 정지 / 일시정지 |
| 5 | Windows 관제 프로그램에서 태그 찍기 | 상품 사진·정보 표시, 로봇 출동 (한/영 키가 영문인지 확인) |
| 6 | 인형 태그 `0B71EC5D` 찍기 | "등록되지 않은 태그입니다", 작업 없음 |

### 1-3. 웹캠 작업 영역 안전 감시 (새 기능)
1. 웹캠을 작업대 전체와 작업자가 다가오는 쪽이 보이게 고정한다.
2. 대시보드 [작업 영역 안전 감시] → **웹캠** 선택 → 영상이 나오는지 확인.
3. 물품 4개를 각 자리에 놓고 **[구역 설정]**으로 구역 1~4 꼭짓점을 4곳씩 찍는다. 처음 값은 화면 4등분이라 실제와 맞지 않는다.
   → Claude에게 대시보드를 보여 주거나 캡처를 보내면 구역을 맞춰 준다.
4. **[경고음·음성 켜기]**를 한 번 누른다(브라우저는 클릭 전에는 소리를 못 냄).
5. 로봇이 물건을 집으러 갈 때 그 구역에 손이나 몸을 넣어 본다:
   경고음 3초 → 로봇 정지 → 비키고 3초 뒤 "안전구역 확보" 음성 → 멈춘 동작부터 재가동. 폰에도 배너·진동이 뜨는지 확인.
6. **실제 로봇에서 `move_stop` 후 같은 목표로 다시 움직이는지 처음엔 천천히** 확인한다(모의 시험에서만 확인됨).

### 1-4. 파지 실패 자동 재시도 (새 기능)
- 빈 그리퍼 판정 기준: 손가락 위치 700 미만, 또는 735 미만이면서 전류가 한계의 80% 이상이면 "물건 있음".
  물품 4개 각각 실제로 집어서 `grasp` 로그의 `position`·`current`가 기준에 맞는지 본다.
- 일부러 빈 곳을 집게 해서: 1회 재시도(열기 → 위로 빠지기 → 다시 찾기 → 다시 집기) → 또 실패하면 정지 + 폰·웹·관제 알림.
  [정지 해제] 후 그리퍼를 열고 홈으로 가는지 확인한다.
- 재시도 횟수: `--grasp-retries N` (기본 1, 0이면 예전처럼 빈 그리퍼로 진행).

### 1-5. 그 밖에 확인
- 재고 관리 화면: 브라우저 PC에 리더기를 꽂고 라벨을 찍으면 재고 수량·보관 위치가 뜨는지(조회만, 로봇 작업 없음).
- 깊이 카메라가 찾은 물품 테두리가 폰 15×15 지도와 대시보드에서 실제 위치와 겹치는지.
- 관제 프로그램이 실습실 노트북 해상도에 맞게 꽉 차는지(1280×720~4K 자동 맞춤).

## 4. 참고
- 회사 PC 테스트: 414개 통과, 16개 실패, 3개 건너뜀. 실패 16개(`test_robot_host_access` 14개 등)는 Windows 임시 파일 권한·`pass_fds` 미지원 같은
  이 PC 환경 문제로, 수정 전 코드에서도 똑같이 실패한다. JS 테스트 2개(음성)도 기존 실패.
- Windows에서 테스트는 `PYTHONUTF8=1`을 켜고 돌린다(한글 파일 읽기 cp949 오류 방지).
- 웹캠 감시·음성은 시연 보조 기능이며 인증된 안전장치가 아니다. **펜던트 E-Stop을 항상 가까이 둔다.**
